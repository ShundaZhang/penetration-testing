检查执行过程
与权限边界

覆盖 Linux / Windows 主机、本地权限、原生代码、逆向和模糊测试。

01 / FIELD NOTES

从进程及其权限开始

进程可通过文件、服务、凭据、IPC 和内核执行动作。

Linux 中检查用户 / 组、sudo 策略、文件权限、Capability、定时任务、服务配置和 Namespace 边界。Windows 中检查访问 Token、服务 / 对象 ACL、计划任务、提权边界和应用配置。区分“低权限用户可修改输入”与“特权进程之后以危险方式消费它”；两者都需证据。

对应资料：MITRE ATT&CK ↗ · NIST SP 800-115：测试与评估 ↗

02 / FIELD NOTES

确定可利用性前先理解 Bug

崩溃、内存破坏原语和稳定安全影响是不同阶段。

方向问题有用证据
解析与内存安全不可信输入能否违反边界、生命周期或类型假设？最小复现、调用栈和 Sanitizer 结果
逻辑 / 授权有效操作能否跨越权限边界？主体、对象及特权效果
缓解机制这里适用哪些内存与进程保护？实际构建参数与运行状态

Ghidra 提供静态分析；调试器及 Frida 提供运行观察。反编译输出是解释，不保证等同源码。应核对类型、控制流、符号假设及实际行为。本地发现不自动等同于远程攻击路径。

对应资料：NSA Ghidra ↗ · Frida 文档 ↗ · MITRE CWE ↗

03 / FIELD NOTES

用合适的 Harness 模糊测试边界

Harness 决定实验能触达哪些代码和状态。

选择输入边界，创建小型有效种子集，插桩覆盖并加入相关 Sanitizer。让 Harness 足够确定，以便复现失败，并在输入间重置状态。按根因归并崩溃、最小化用例并判断安全相关性。每秒执行次数更多，不能弥补无法到达关键解析器的 Harness。

对应资料：AFL++ 文档 ↗

04 / FIELD NOTES

评审交付与恢复边界

主机安全还依赖更新信任、本地秘密和运行状态。

检查哪个身份能安装或替换可执行文件、谁控制配置、更新怎样验证以及回滚后保留什么。授权影响验证可用无害标记或受控读取示例数据来证实边界跨越，无需收集无关主机数据。记录准确清理状态，并核验恢复后服务行为正常。

对应资料：NIST SP 800-115：测试与评估 ↗ · MITRE ATT&CK ↗
