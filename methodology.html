01 / FIELD NOTES

The assessment loop

Discovery changes the next hypothesis; evidence changes the next decision.

Plan the objective and boundaries. Discover assets and behaviors. Form a specific hypothesis with a falsifiable expectation. Validate with a controlled comparison. Record preconditions, evidence and observed impact. Explain root cause, recommend a change and retest the same property. Keep a separate coverage ledger for blocked or untested paths.

02 / FIELD NOTES

Combine methods with different blind spots

No single scanner, framework or access level sees the whole system.

MethodStrengthBlind spot / follow-up
Design / threat-model reviewMissing boundaries and unsafe assumptionsMust validate deployed behavior
SAST / code reviewData flow and hidden pathsReachability, framework semantics and runtime config
DAST / manual requestsActual runtime responsesOnly tested identities, states and reachable paths
Configuration / permission reviewEffective policy and excessive trustPolicy combinations and changing state
FuzzingUnexpected parser states and crashesHarness quality and semantic correctness

03 / FIELD NOTES

Make comparisons that isolate the cause

Change one meaningful variable at a time, then test the result against a control.

Test questionMethod / evidenceInterpretation
Is this access control broken?Compare owner, non-owner, other tenant and anonymous requests on the same fixtureA 200 status is not sufficient; inspect protected fields and object ownership
Is this a state-machine failure?Compare normal order, repeated request and forbidden transitionDistinguish application invariants from transport retries
Is an input causing a backend effect?Use paired benign inputs and trace correlation in a controlled environmentA timing difference alone may reflect caching, load or rate limiting
