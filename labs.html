Practice the reasoning
See what the result proves

Four deterministic browser exercises with synthetic data. They make no target requests, execute no tools and use no model service. All results are local simulations.

01 / AUTHORIZATION

Inspect the authorization matrix

Expected rule: ordinary users read only their own invoices; managers read/update within their tenant.

Ready — choose a case

Compare expected and observed decisions, then change the implementation. The local functions deliberately model common omissions; they are not a server or a deployment-ready access-control library. A 200 response without protected data would not by itself establish a read failure.

02 / EVIDENCE

Keep the claim within the evidence

Read the provided synthetic observation, choose a conclusion and compare the reasoning.

Ready — choose a case

The categories describe support for a claim, not severity. A severe hypothetical consequence can still be based on an unverified signal.

03 / COVERAGE

Count what you actually examined

Planned matrix: four identities × two actions × two session states = 16 cases.

Ready — choose a case

The ledger is synthetic and distinguishes examined, blocked and not-run cases. Its percentage measures coverage of this stated matrix, not absence of vulnerabilities or overall security. Real coverage also needs routes, inputs, vantage and business state.

Read the source: NIST SP 800-115: testing and assessment ↗ · OWASP WSTG v4.2 ↗

04 / AGENT AUTHORITY

Preserve the original task’s capability

Fixed task: an ordinary tenant-A user asks to read one tenant-A document. The connector has broad synthetic credentials.

Ready — choose a case

Changing the proposal’s origin does not expand the task’s allowed actions. The strict gate checks the existing task capability and user/resource permission. This is a deterministic authority simulation, not a real prompt-injection or LLM benchmark.
