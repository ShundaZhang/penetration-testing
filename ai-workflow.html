01 / FIELD NOTES

Useful assistance has a bounded input and output

Judge the result against a checkable task, not the fluency of the answer.

TaskAI can help withHuman / deterministic check
Recon synthesisNormalize inventory and propose missing questionsVerify asset ownership and source provenance
Code reviewExplain a data flow and suggest testsTrace the real source/sink and reachable code path
Test generationDraft fixtures, parsers and regression casesReview behavior, isolation and assertions before execution
Triage / reportingGroup observations and draft clear explanationsLink every impact claim to saved evidence

The enduring skill is knowing which observation would disprove the suggested hypothesis. Treat an invented CVE, incorrect flag or plausible explanation as a candidate to verify, not as evidence.

02 / FIELD NOTES

Keep policy enforcement outside the model

A natural-language instruction is not a reliable authorization boundary.

Use a planner to propose an action, a deterministic runner to enforce scope and budgets, and a recorded result for evaluation. Validate target normalization, redirects, DNS resolution and tool arguments at execution time. Separate discovery, read-only queries, write operations and destructive actions with explicit capabilities. Bound retries, time, cost, concurrency and credential access. A page or tool response can contain hostile instructions, so label it as data and never let it grant a new capability.

03 / FIELD NOTES

The testing assistant is itself a data boundary

Source code, credentials and captured responses can outlive the test if sent to another system.

Use an approved processing environment, synthetic or minimized examples, and explicit retention rules. Redact tokens and unrelated records before prompting. Keep command execution isolated, pin dependencies and record model/tool versions. External response text is untrusted even when retrieved by a trusted scanner. Human review should focus on scope changes, side effects and evidence sufficiency rather than mechanically approving every suggestion.

04 / FIELD NOTES

Read AI testing benchmarks as experiments

A laboratory completion rate does not measure organization-wide assurance.

PentestGPT and automated-testing papers provide useful research on planning, context and tool interaction. Their reported results depend on task sets, model versions, hints, allowed tools and success definitions. For your own evaluation, use held-out tasks, a fixed budget, control baselines and independently checked effects. Report failure cases, false positives, unsafe actions and human intervention alongside success. A model-as-judge score needs validation against real outcomes.
