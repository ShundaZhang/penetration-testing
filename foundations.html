01 / FIELD NOTES

Several assessments answer different questions

Choose the objective before choosing the tool.

AssessmentMain questionTypical output
Vulnerability scanningWhich known weaknesses or misconfigurations may be present?Candidates requiring triage
Penetration testingCan a defined attacker violate a security property within the agreed scope?Reproducible findings, impact and coverage limits
Red teamingCan the organization prevent, detect and respond to an objective-driven adversary?Attack-path and detection/response observations
Purple teamingCan controlled adversary behavior improve defensive controls?Validated detections and control improvements

CTFs train problem solving in an intentionally constrained environment. A flag is a useful exercise milestone; a client assessment additionally needs scope, evidence, business context, cleanup and a retest plan.

02 / FIELD NOTES

Represent the system as principals and boundaries

A vulnerability usually crosses a boundary the design intended to preserve.

Name the asset, actor, entry point, privilege, action and expected property. Draw data flows and trust boundaries. STRIDE can generate questions about spoofing, tampering, repudiation, disclosure, denial of service and privilege elevation; an attack tree decomposes an objective into alternative or combined prerequisites. Neither is a complete test plan on its own.

Claim: tenant A must not read tenant B’s invoices
Actor: ordinary user in tenant A
Action: read invoice owned by tenant B
Expected: server-side denial without protected data
Evidence: paired requests, identities, object ownership and response body

03 / FIELD NOTES

Knowledge and location are independent axes

Black, gray and white box describe supplied knowledge; internal and external describe vantage.

White-box access can reveal unreachable code and policy design; black-box testing emphasizes observable behavior. Authenticated versus unauthenticated testing changes the principal, not just the scanner switch. Coverage is the set of properties and paths actually examined from those identities and locations. A clean scan or unsuccessful attempt does not prove absence of vulnerabilities.

Confidence is a separate dimension

Keep severity, confidence and test coverage separate. A dramatic hypothetical impact does not turn a weak observation into a confirmed finding.

04 / FIELD NOTES

Define an engagement that can be reproduced

The scope is an engineering input to the test.

  • Record assets, owners, allowed identities, environments, time window and excluded dependencies. A shared IP or redirect does not automatically add a third-party service to scope.
  • Agree on permitted actions, request budgets, account-lockout behavior, handling of sensitive evidence, stop conditions and recovery contacts.
  • Use synthetic records and the least intrusive proof that establishes the property failure; track changes that must be reversed.
