01 / FIELD NOTES

A device has more than one interface

Map manufacturing, enrollment, operation, update and retirement.

Inventory debug ports, local buses, radio interfaces, firmware images, boot/update verification, device identity and cloud APIs. UART, JTAG or an extracted filesystem is an observation surface, not automatically a vulnerability: the attack model and production configuration matter. Follow how a device acquires secrets, authenticates a controller, verifies updates and handles reset or ownership transfer.

Analyze artifacts before changing a live device

Offline inspection provides a lower-impact entry point.

03 / FIELD NOTES

OT assessment includes process constraints

Availability and physical safety change the acceptable test method.

Model the process, controller, engineering workstation, historian and remote access path. Begin with architecture, configuration and passive traffic review; use a representative test rig for active parser and command tests. Agree maintenance windows and recovery with the process owner. A protocol write or aggressive probe may change the physical process, so an ordinary IT scan profile is not automatically appropriate.

Version the reference

NIST SP 800-82 Rev. 3 supplies OT context. The OWASP IoT project includes older risk lists; use them as orientation and validate platform-specific behavior with current vendor documentation.
