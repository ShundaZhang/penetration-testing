把观察结果
变成有效修复

学习证据、严重性、不确定性、根因、修复及回归测试。

01 / FIELD NOTES

明确证据层级

不要让结论超出实验。

层级例子可支持的结论
信号Banner、模板告警或异常响应需要调查候选项
复现行为同一请求对产生可重复差异该行为在给定条件下可重复
已确认边界失败非所有者读取受保护示例记录该身份和对象的被测属性失败
已展示影响限定流程到达约定受保护资产所展示影响发生；更广影响仍是推断

对应资料：NIST SP 800-115：测试与评估 ↗

02 / FIELD NOTES

写出别人能复现的发现

有效报告连接被违反属性、观察结果及修复。

Title: Cross-tenant invoice read
Expected property: tenant A cannot read tenant B’s invoice
Scope / build / time / identities: ...
Preconditions: two synthetic tenant accounts and invoice fixtures
Reproduction: paired owner and non-owner requests
Observed result: protected tenant-B fields returned to tenant A
Evidence: redacted request IDs, response body, ownership map
Root cause: object query lacks tenant-scoped authorization
Fix: enforce principal + tenant + object permission server-side
Retest: owner allowed, other tenant denied, alternate routes checked
Limits: write access and historical deployments not tested

安全保存原始证据，仅展示所需最小片段。截图有助解释，但不替代请求 / 响应标识、策略状态或可复现示例。未经验证的可能性应如实标为可能性。

对应资料：NIST SP 800-115：测试与评估 ↗ · OWASP ASVS 5.0.0 ↗

03 / FIELD NOTES

严重性、利用可能性与业务风险

这些量回答不同问题。

CVSS v4.0 用明确指标和向量描述技术严重性，不是独立业务风险分数。EPSS 估计已发布 CVE 在其时间窗口内被真实利用的概率，不预测你的具体测试是否成功，也不直接评分新的逻辑 Bug。修复优先级还应加入资产暴露、数据敏感度、受影响权限、控制和置信度，并解释数值背后的理由。

对应资料：FIRST CVSS v4.0 规范 ↗ · FIRST EPSS ↗

04 / FIELD NOTES

复测属性，而不只复测旧输入

修复应保留有效行为，同时阻止禁止动作。

重复原始受控案例，核验合法访问，并测试共享根因的其他路由、身份和状态。可行时把示例转成回归测试。拦截某字符串的 WAF 规则未必修复后端属性。区分已修复、部分修复、未修复和未复测，核验清理并报告剩余覆盖限制。

对应资料：OWASP ASVS 5.0.0 ↗ · NIST SP 800-115：测试与评估 ↗
