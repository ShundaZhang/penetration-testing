01 / LEARNING ROUTE

Build depth one assessed system at a time

Assumed background: programming and operating-system familiarity. Add HTTP, TCP/IP, identity and cloud basics when a chosen direction needs them. The schedule is optional.

01

Get oriented in two evenings

Read Foundations and Methodology. Explain scanning versus penetration testing, name a property and draft an assessment scope. Run the evidence and coverage exercises.

02

Complete one application assessment

Over one to two weeks, study Web / API with an isolated lab or Academy exercise. Capture paired requests, validate one finding, fix it and retest. Learn a proxy before adding automation.

03

Choose a specialization

Spend two to four weeks on Network, Identity / AD, Cloud, Host / binary, Mobile or IoT / OT. The domains are independent: choose according to the systems you work with.

04

Add AI and a reproducible report

Study AI-assisted testing and AI system security separately. Over one to two weeks, evaluate a bounded helper task and one synthetic agent boundary. Write the evidence and retest plan.

02 / DIRECTIONS

Choose your test surface

Each domain has its own entry point. You can use the common method without forcing every domain into one attack chain.

03 / FIRST PROJECT

The smallest useful deliverable

A first assessment should be small enough to explain every request and decision.

TEST

Two users, two objects, one property

Compare owner and non-owner reads in a training application. Keep identities and fixtures explicit.

REPORT

One finding, one fix, one retest

State the expected property, observed effect and limits. Verify the fixed behavior and legitimate access.
