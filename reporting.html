01 / FIELD NOTES

Keep the evidence ladder visible

Do not let the conclusion outrun the experiment.

LevelExamplePermitted conclusion
SignalA banner, template alert or unusual responseInvestigate a candidate
Reproduced behaviorThe same request pair produces a repeatable differenceThe observed behavior is repeatable under stated conditions
Confirmed boundary failureA non-owner reads a protected synthetic recordThe tested property failed for this identity and object
Demonstrated impactA scoped workflow reaches the agreed protected assetThe shown impact occurred; broader impact remains an inference

02 / FIELD NOTES

Write a finding someone else can reproduce

A useful report connects the violated property to the observed result and the fix.

Title: Cross-tenant invoice read
Expected property: tenant A cannot read tenant B’s invoice
Scope / build / time / identities: ...
Preconditions: two synthetic tenant accounts and invoice fixtures
Reproduction: paired owner and non-owner requests
Observed result: protected tenant-B fields returned to tenant A
Evidence: redacted request IDs, response body, ownership map
Root cause: object query lacks tenant-scoped authorization
Fix: enforce principal + tenant + object permission server-side
Retest: owner allowed, other tenant denied, alternate routes checked
Limits: write access and historical deployments not tested

Preserve raw evidence securely and publish only the minimum needed excerpt. Screenshots help explain a result but should not replace request/response identifiers, policy state or a reproducible fixture. Describe untested possibilities as possibilities.

03 / FIELD NOTES

Severity, exploitation likelihood and business risk

These quantities answer different questions.

CVSS v4.0 describes technical severity with explicit metrics and a vector; it is not a standalone business-risk score. EPSS estimates the probability of exploitation of a published CVE in the wild over its stated horizon; it does not predict the success of your specific test or directly score a new logic bug. Add asset exposure, data sensitivity, affected privileges, controls and confidence to remediation priority. Give the reasoning alongside any number.

04 / FIELD NOTES

Retest the property, not just the old payload

The fix should preserve valid behavior while blocking the forbidden action.

Repeat the original controlled case, verify legitimate access and test alternate routes, identities and states sharing the root cause. Turn the fixture into a regression test where practical. A WAF signature that blocks one string may not repair the backend property. Keep fixed, partially fixed, not fixed and not retested separate; verify cleanup and report residual coverage limits.
