Web and API weaknesses emerge at authorization boundaries, parser boundaries and business invariants.

01 / FIELD NOTES

Model requests beyond the URL

An endpoint is a method, identity, object, input schema and state transition.

Inventory routes from the application, documentation and observed traffic. Include REST, GraphQL, WebSocket and asynchronous jobs where present. Record authentication context, tenant, object owner, output fields and backend dependencies. Separate an undocumented route from an exposed sensitive action; discovery alone is not impact.

02 / FIELD NOTES

Build a principal × object × action matrix

Authentication proves an identity; authorization decides whether that identity may perform this action.

Test questionMethod / evidenceInterpretation
Object-level accessCompare two ordinary users and two tenant fixturesChanging an identifier must not cross ownership or tenant boundaries
Function-level accessCall administrative actions with the ordinary-user identityHidden UI controls are not server-side authorization
Property-level accessCompare allowed fields on read and update pathsMass assignment and excessive output can fail independently
Token lifecycleCheck expiry, logout, rotation and audience boundaries using test identitiesA token accepted by one service should not imply access to another

03 / FIELD NOTES

Trace the boundary each class breaks

Understand the mechanism before memorizing payloads.

ClassRoot questionEvidence to seek
SQL / command injectionDoes data become executable syntax?Input-to-sink path and a controlled backend effect
XSS / template injectionWhich rendering context interprets the input?Actual browser or template execution context, not just reflection
SSRFCan caller input control a server-side destination?Destination policy, redirects, address resolution and network vantage
CSRF / session handlingWho can cause an authenticated state change?Browser credentials, origin handling and anti-CSRF behavior
Deserialization / uploadDoes an untrusted object acquire dangerous semantics?Type restrictions, storage/execution separation and parser behavior
Request smuggling / cache confusionDo intermediaries disagree about message or cache boundaries?A repeatable differential effect in a controlled proxy chain

04 / FIELD NOTES

Business logic needs invariants and state

A syntactically valid request may still be an invalid business action.

Write invariants such as “one voucher is redeemed once”, “a transfer cannot skip approval” or “refunds cannot exceed captured value”. Test role changes, replay, alternate order and concurrency against synthetic fixtures. Count durable backend effects rather than successful HTTP responses. For race tests, use a small bounded concurrency budget and a resettable local lab.
