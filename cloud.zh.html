01 / FIELD NOTES

评估有效权限链

云中可达与云中可控不是一回事。

追踪主体 → 凭据 / 会话 → 适用策略 → 动作 → 资源。AWS 决策可能涉及身份策略、资源策略、边界、会话策略及组织控制；应核对其准确交互，而非假设权限简单相加。检查角色信任、谁能承担或传递角色，以及工作负载能否获得超出预期的身份。云厂商测试政策也属于约定范围的输入。

对应资料：AWS IAM 策略求值 ↗

02 / FIELD NOTES

配置发现需要具体访问问题

态势检查说明要调查什么；受控动作说明实际能做什么。

测试问题方法 / 证据结果解释
对象存储用示例对象核验匿名、租户和工作负载访问公开策略、列举和读取是不同动作
工作负载元数据 / 秘密评审身份可获得性、网络限制和 Token 受众返回标识符不等于可使用的特权凭据
交付流水线追踪仓库权限、Runner 信任、构建秘密和部署身份区分制品完整性与部署授权

03 / FIELD NOTES

Kubernetes 存在多种相互作用的边界

RBAC、工作负载隔离、网络策略及节点边界回答不同问题。

记录 API 接入、服务账号、RoleBinding / ClusterRoleBinding、准入策略、Secret、容器 Capability、宿主挂载及网络策略执行。Namespace 是组织和策略范围，本身不保证租户隔离。特权容器或宿主访问可能削弱 Pod / 节点边界。kube-bench 配置结果和镜像 CVE 报告不证明运行时逃逸成功。

对应资料：Kubernetes 安全概念 ↗ · kube-bench ↗ · Trivy 文档 ↗

04 / FIELD NOTES

建立小型账号与集群靶场

从只读清单开始，用可丢弃示例验证限定权限。

创建两个身份、两个权限刻意不同的存储对象，比较预期策略与实际访问，再修复并重复。Kubernetes 练习中记录服务账号权限及本地集群中一个应被拒绝的动作。Prowler 与 ScoutSuite 有助整理态势观察；在测试记录中明确它们收集的账号数据和 API 权限。

对应资料：Prowler 文档 ↗ · NCC Group ScoutSuite ↗ · Kubernetes 安全概念 ↗
